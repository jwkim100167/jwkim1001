# 컴포넌트 분리 리팩토링

**입력:** $ARGUMENTS
(형식: `파일경로 / 분리 목표`. 예: `src/components/games/cobra/CobraGamePlay.jsx / 보드·손패·액션버튼을 각각 분리`)

아래 순서대로 4개의 에이전트를 실행해서 큰 컴포넌트를 역할별 서브 컴포넌트로 분리한다.

---

## 프로젝트 맥락 (모든 에이전트 공통)

- React 19 + Vite SPA, 컴포넌트마다 sibling `.css` 파일 존재
- CSS 프레임워크 없음, 각 컴포넌트는 고유 className prefix 사용
- 파일 위치: `src/components/{domain}/{name}.jsx`
- 기존 패턴 참조: 각 게임 폴더 내 `{Game}Game.jsx` / `{Game}Play.jsx` 구조

---

## 에이전트 1 — 탐색 (가장 먼저 실행)

**역할:** 대상 파일을 읽고 분리 가능한 단위를 파악한다.

1. 대상 파일 전체를 읽는다
2. 다음을 파악한다:
   - 전체 줄 수, state 목록, useEffect 목록
   - 렌더링 블록별 역할 (보드, 손패, 액션 버튼, 모달, 로그 등)
   - 각 블록이 의존하는 props/state 목록
   - CSS 파일에서 각 블록에 해당하는 클래스 목록
3. 다음을 반환한다:
   - 추천 분리 단위 (컴포넌트명 + 역할 + 담당 state/props)
   - 분리 후 예상 파일 목록
   - 분리 시 주의사항 (공유 state, 콜백 전달 방식 등)

---

## 에이전트 2 — 계획 (에이전트 1 완료 후)

**역할:** 에이전트 1 결과를 바탕으로 구체적인 분리 설계를 확정한다.

1. 각 서브 컴포넌트의 props 인터페이스를 정의한다:
   ```
   <ComponentName prop1={} prop2={} onAction={} />
   ```
2. 부모 컴포넌트가 state를 어떻게 관리하고 자식에게 내려줄지 설계한다
3. CSS 분리 전략을 결정한다 (파일 분리 vs 기존 파일 유지)
4. 분리 순서를 결정한다 (독립적인 것부터)
5. 설계 결과를 반환한다

---

## 에이전트 3 — 수정 (에이전트 2 완료 후)

**역할:** 에이전트 2의 설계대로 실제 파일을 생성/수정한다.

원칙:
- 수정 전 반드시 파일을 다시 읽는다
- 기능 변경 없이 구조만 바꾼다 (동작은 동일해야 함)
- 서브 컴포넌트를 먼저 만들고, 마지막에 부모를 수정한다
- CSS는 별도 분리하지 않고 기존 파일 유지 (특별히 요청하지 않는 한)
- 수정 완료 후 변경된 파일 목록과 각 컴포넌트의 역할 요약을 반환한다

---

## 에이전트 4 — QA (에이전트 3 완료 후)

**역할:** 분리된 코드를 검토하고 검증 방법을 안내한다.

### 코드 리뷰
- props 누락 없는지 (부모가 내려줘야 할 것들이 다 전달되는지)
- state 중복 선언 없는지
- 콜백 함수가 올바르게 연결되는지
- import 경로가 정확한지

### 수동 검증 체크리스트
1. `npm run dev` → 분리된 컴포넌트가 있는 화면으로 이동
2. 기존과 동일하게 렌더링되는지 확인
3. 각 인터랙션(버튼 클릭, 입력 등)이 정상 동작하는지 확인
4. 콘솔 에러 없는지 확인
