# 게임 버그/오류 수정

**입력:** $ARGUMENTS
(형식: `게임명 / 증상 설명`. 예: `코브라 / 호스트가 나가면 게임이 멈춤`)

아래 순서대로 3개의 에이전트를 실행해서 버그를 찾고 수정한다.

---

## 프로젝트 맥락 (모든 에이전트 공통)

- React 19 + Vite SPA, Supabase 백엔드
- 게임 파일 위치:
  - 서비스: `src/services/games/supabase{GameName}.js`
  - 컴포넌트: `src/components/games/{game}/`
  - 유틸: `src/utils/games/{game}Logic.js` (존재하는 경우)
- 기존 멀티플레이어 게임: Cobra, Blokus, Akinator, TurneyKia, Typing, HalliGalli, (벽바둑 추가 시 Byukbaduk)

---

## 에이전트 1 — 탐색 & 원인 분석

**역할:** 버그와 관련된 모든 코드를 읽고 원인을 찾는다.

입력에서 게임명과 증상을 파악한 뒤 다음을 수행한다:

1. `docs/games/{game}.md` 파일이 존재하면 먼저 읽어 의도된 게임 흐름과 상태 구조를 파악한다.
   (존재하지 않으면 건너뜀)
2. 해당 게임의 서비스 파일, 컴포넌트 파일 전체를 읽는다
3. 증상과 관련된 코드 경로를 추적한다:
   - Realtime 구독/해제 로직
   - 호스트 승계 로직
   - 게임 상태 업데이트 흐름
   - useEffect cleanup 존재 여부
   - 비동기 처리 (race condition 가능성)
4. 버그 원인을 특정하고 다음을 반환한다:
   - **원인**: 어느 파일, 몇 번째 줄, 왜 문제인지
   - **재현 조건**: 어떤 순서로 행동하면 버그가 발생하는지
   - **수정 방향**: 어떻게 고쳐야 하는지 (코드 변경 전 계획)
   - **영향 범위**: 이 수정이 다른 기능에 영향을 줄 수 있는지

---

## 에이전트 2 — 수정 (에이전트 1 완료 후)

**역할:** 에이전트 1의 분석을 바탕으로 최소한의 변경으로 버그를 수정한다.

원칙:
- 버그 수정에 필요한 코드만 변경한다 (불필요한 리팩터링 금지)
- 수정 전 반드시 해당 파일을 다시 읽고 현재 상태를 확인한다
- 변경 사항마다 이유를 주석이나 설명으로 남긴다
- 수정 후 변경된 파일 목록과 변경 내용 요약을 반환한다

---

## 에이전트 3 — QA & 검증 (에이전트 2 완료 후)

**역할:** 수정된 코드를 검토하고 검증 방법을 안내한다.

다음을 수행한다:

### 코드 리뷰
- 수정된 코드가 원인을 실제로 해결하는지 확인
- 수정으로 인한 새로운 버그 가능성 체크
- 비슷한 패턴의 다른 게임에 같은 버그가 있는지 확인 (있으면 목록 출력)
- `docs/games/{game}.md`가 존재하면:
  - 버그 수정으로 게임 흐름(Mermaid 다이어그램)이나 game_state 구조가 바뀌었는지 확인
  - 바뀐 경우 해당 섹션을 직접 업데이트한다
  - 바뀌지 않은 경우 "기획서 변경 없음" 명시

### 수동 검증 체크리스트 출력
개발자가 `npm run dev` 후 직접 확인해야 할 단계별 시나리오:
1. 버그 재현 순서 그대로 따라해서 수정됐는지 확인
2. 정상 플로우(방 생성 → 입장 → 플레이 → 종료)가 여전히 동작하는지 확인
3. 엣지 케이스 (1명만 남은 경우, 새로고침, 뒤로가기 등) 확인
