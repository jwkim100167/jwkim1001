# 중복 코드 추출 리팩토링

**입력:** $ARGUMENTS
(형식: `도메인 / 설명`. 예: `games / 게임 서비스 5개의 createRoom·joinRoom 등 공통 함수 추출`)

아래 순서대로 4개의 에이전트를 실행해서 중복된 로직을 공통 파일로 추출한다.

---

## 프로젝트 맥락 (모든 에이전트 공통)

- React 19 + Vite SPA, Supabase 백엔드
- 도메인 폴더 구조: `src/services/{domain}/`, `src/components/{domain}/`, `src/utils/{domain}/`
- 현재 중복이 많은 영역:
  - `src/services/games/` — 5개 게임 서비스에 createRoom, joinRoom 등 70~80% 중복
  - `src/components/lifestyle/` — BonusHub, TasteHub 렌더링 패턴 90% 중복
- 기존 공통 유틸 위치: `src/utils/`, `src/services/core/`

---

## 에이전트 1 — 탐색 (가장 먼저 실행)

**역할:** 중복 범위를 정확히 파악한다.

1. 도메인 내 관련 파일들을 모두 읽는다
2. 다음을 파악한다:
   - 완전히 동일한 함수 목록 (파일명 + 함수명)
   - 거의 동일하되 테이블명/필드명 등 상수만 다른 함수 목록
   - 추출 불가 (각 파일 고유 로직) 목록
3. 다음을 반환한다:
   - 추출 가능한 함수 목록과 차이점 분석
   - 공통 파일 경로 제안 (예: `src/services/games/gameRoomBase.js`)
   - 추출 전략 (팩토리 패턴 vs 고차함수 vs 직접 import 등)
   - 각 기존 파일의 변경 범위

---

## 에이전트 2 — 설계 (에이전트 1 완료 후)

**역할:** 공통 인터페이스를 설계한다.

1. 공통 파일의 함수 시그니처를 확정한다
2. 각 기존 파일이 공통 함수를 어떻게 사용할지 결정한다:
   - 직접 re-export: `export { createRoom } from './gameRoomBase.js'`
   - 래퍼로 호출: `export async function createRoom(...) { return baseCreateRoom('cobra_rooms', ...) }`
3. 하위 호환성 확인 (기존 import 경로 변경 여부)
4. 설계 결과 반환

---

## 에이전트 3 — 수정 (에이전트 2 완료 후)

**역할:** 실제로 공통 파일 생성 및 기존 파일 수정.

원칙:
- 각 파일을 수정 전 반드시 읽는다
- 공통 파일 먼저 생성 → 이후 기존 파일 수정
- 기존 export 인터페이스는 유지 (컴포넌트 import 경로 변경 없도록)
- 한 번에 한 파일씩 수정하고 확인
- 수정 완료 후 생성/수정된 파일 목록 + 줄 수 감소량 반환

---

## 에이전트 4 — QA (에이전트 3 완료 후)

**역할:** 수정된 코드 검토 및 검증 안내.

### 코드 리뷰
- 공통 함수의 파라미터가 모든 사용처를 커버하는지
- 기존 export가 모두 유지되는지 (외부 import 깨지지 않는지)
- 엣지 케이스 처리 누락 없는지

### 수동 검증 체크리스트
1. `npm run dev` → 콘솔 에러 없는지 확인
2. 중복 추출 대상이었던 기능들(예: 방 생성, 입장) 직접 실행 확인
3. 각 게임/화면별로 기존과 동일하게 동작하는지 확인
4. `npm run build` → 빌드 에러 없는지 확인
